# Node refinement (in progress, not a gate)

This directory holds unfinished M2 work: a refinement from the generated
`Node` (fixed engine: hooks absent, peers equal to members) to the
[election-safety](../election-safety/Model.lean) model. It has no
`project.json`, so `assert_proofs!` and `verify.sh` do not check it and it
makes no claim. Check it by hand:

```sh
jarl/proofs/node-refinement-wip/build.sh <work-dir> all
```

The script generates Lean for `Node::tick`, `step`, `next_message`, `build`
and `Ready::persisted` ([generator.json](generator.json)), then elaborates
Provium and the modules below with `--trust=0`, warnings as errors.

| Module | Contents | Status |
| --- | --- | --- |
| [Refine.lean](Refine.lean) | Value encodings (`Fields`, `idv`, `statev`, …), `Calm`, `Good`, `Campaigned`, and specs for every helper `step`/`tick` call plus `tick_spec` | complete |
| [Abstract.lean](Abstract.lean) | The abstraction `Abs` from node fields to the model's `Local`; lifting of calm steps and campaigns | complete |
| [StepDefs.lean](StepDefs.lean) | Uniform helper specs, check lemmas, `calm_tac`, `subst_reads`, and `StepOut`, the per-message outcome of `step` | complete |
| [Persist.lean](Persist.lean) | `Ready::persisted` | complete |
| [AbsStep.lean](AbsStep.lean) | Outbox and majority lemmas; `Abs` lemmas mapping each `StepOut` arm to the model: `Abs.vote` (`handleVote`), `Abs.voted` (`handleVoted`), `Abs.prevote` (`answerProbe`), `Abs.adopt_calm` (`PreVoted`, `Replicated`), `Abs.follow` (`Append`, `AppendBatch`, `Install`: unchanged or `demote ∘ adopt`) | complete |
| `StepCase_<kind>.lean` | One `step` proof per message kind (`Replicated` split by rejection), generated by [gen/step_cases.py](gen/step_cases.py) from [gen/step_proof_template.txt](gen/step_proof_template.txt) and `gen/tail_<kind>.txt`; `AppendBatch` uses a loop invariant over its entries | complete |
| [Step.lean](Step.lean) | `step_spec`: the cases combined, for a node whose stored vote is absent or a member id (which `Abs` provides) | complete |

Remaining before this can become a gated project: specs for `next_message` and
`build`, the world simulation (composing `tick_spec`, `step_spec` and the `Abs`
lemmas into `Jarl.ElectionSafety.Step` sequences) and the implementation-level
election-safety theorem.
